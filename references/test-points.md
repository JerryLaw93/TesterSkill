# 测试点分析（6 维度）

每收到一个需求 / 一个页面，按以下 6 维度扫一遍，自然能覆盖 80% 缺陷。

## 1. 功能（Happy Path）

- 每个按钮 / 每个链接 / 每个表单字段 = 至少 1 条正向用例
- 入口、出口、必经路径 = 必测
- 状态机：每个状态切换都测一次

## 2. 边界（Boundary）

| 维度 | 边界值 |
|---|---|
| 长度 | 0 / 1 / 最小-1 / 最大 / 最大+1 / 10000 |
| 数字 | 0 / 1 / -1 / 最小值 / 最大值 / 浮点 / 0.0 |
| 时间 | 1970 / 2000 / 2038 / 2099 / 闰年 2-29 / 月末 / 年末 |
| 字符串 | 空 / 全空格 / 单字符 / 超长 / Unicode / Emoji |
| 列表 | 空 / 单条 / 千条 / 重复元素 |

## 3. 异常（Negative）

- 输入校验：类型错、格式错、必填空、重复
- 权限：无权限 / 过期 / 错角色 / 跨用户
- 数据：脏数据 / 删除后引用 / 软删 / 硬删
- 流程：跳过中间步骤 / 重复提交 / 并发

## 4. 权限（Permission）

- 页面级：哪些角色能进 / 不能进（默认隐藏 + 直接访问 URL 两种都要测）
- 按钮级：能看到但禁用 / 完全不可见 / 绕过前端直接调 API
- 数据级：A 用户能否读 / 改 B 用户的数据
- 默认角色：新建账号默认权限是否符合预期

## 5. 性能（Performance）

- 首屏时间（< 2s）
- 接口 P95 < 500ms
- 千行列表滚动不卡
- 频繁点击不重复提交

## 6. 安全（Security）

- XSS：`<script>alert(1)</script>` 进文本框，看输出是否转义
- SQL 注入：`' OR 1=1 --`
- CSRF：跨站请求是否带 token
- 密码：是否明文存储 / 传输 / 显示
- 验证码：是否可绕过 / 暴力破解
- 会话：登出后旧 token 是否还能用
- 越权：低权限用户是否能调高权限接口

## 用例规模经验值

| 模块大小 | 建议用例数 |
|---|---|
| 一个简单列表页 | 8 ~ 15 |
| 一个 CRUD 页面 | 20 ~ 35 |
| 一个含权限的模块 | 30 ~ 50 |
| 登录 + 会话 | 10 ~ 20 |
| 端到端主流程 | 5 ~ 10 |
